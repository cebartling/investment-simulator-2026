# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build system

This is a macOS SwiftUI app built entirely from the command line with Swift Package Manager. There is no `.xcodeproj` and the Xcode IDE is never used, but Xcode must be installed and selected: Command Line Tools alone lack the Swift Testing module (`no such module 'Testing'`) and the SwiftUI `#Preview` macro plugin. Do not add `#Preview` blocks; they break builds without Xcode.app and have no use here.

All tasks go through the `justfile`:

- `just build`: debug build
- `just test`: run all tests (Swift Testing)
- `swift test --filter MoneyTests`: run a single suite (or `--filter <Suite>/<test>`)
- `just run`: launch the app straight from SwiftPM
- `just bundle`: release build wrapped into `build/Investment Simulator.app`, signed ad-hoc unless `CODESIGN_IDENTITY` names a Developer ID (which adds hardened runtime and a timestamp). `just bundle 1.2.3 42` also stamps that version and build number into the bundled `Info.plist` before signing.
- `just release-zip <version>`: zip the `.app` as `build/Investment-Simulator-<version>.zip`
- `just notarize <version>`: notarize that zip, staple the `.app`, check it with `stapler validate` and `spctl`, then re-zip it. Needs `NOTARY_KEY_PATH`, `NOTARY_KEY_ID` and `NOTARY_ISSUER_ID`.
- `just open`: bundle, then open the `.app`
- `just format`: SwiftFormat in place
- `just lint`: SwiftFormat in lint mode plus `swiftlint lint --strict`; CI fails on any violation
- `just clean`: `swift package clean` plus removing `build/`

## Architecture

The project follows Hexagonal Architecture ([ADR-0001](docs/adr/0001-hexagonal-architecture.md)). Decisions are recorded as ADRs in `docs/adr/`; read them before changing structure, and add one for any new architectural decision.

Targets (those marked *planned* don't exist yet; create each one with its test target when the first code needs it):

- `InvestmentSimulatorCore` (library): the hexagon. Domain model, use cases, and ports as protocols. Imports only Foundation, never SwiftUI, AppKit, SwiftData or networking. Put anything testable here.
- `InvestmentSimulatorPresentation` (library, ADR-0004): `@Observable` presentation models, one per screen. Depends on Core; imports only Foundation, Observation and Core, never SwiftUI or AppKit.
- `InvestmentSimulatorPersistence` (library, ADR-0021): the GRDB adapter implementing Core's `ExperimentRepository` port, the schema and its migrations (ADR-0021). Money is stored as a decimal string, never a number. The JSON codec and DTOs from ADR-0005 remain until they are deleted.
- `InvestmentSimulatorMarketData` (library, ADR-0012): the Equibles adapter implementing Core's `QuoteProviding` port, plus the Research adapters (ADR-0019), all over an injected `HTTPTransport`, so their tests never reach the network.
- `InvestmentSimulator` (executable): thin SwiftUI views and the composition root, which builds adapters and presentation models and passes them down through initializers. Adapters and services never go in `@Environment`. The app has no tests.
- Every library target has a matching `…Tests` target using Swift Testing (ADR-0007). Driven ports are faked in memory; no test touches disk, network, the real clock or system randomness.

**Terminology:** ADR-0005 says *scenario*; the code and UI say *experiment* (`Experiment`, `ExperimentRepository`). They are the same concept.

Rules from the accepted ADRs:

- **Money (ADR-0002):** amounts are Core's `Money` type wrapping `Decimal`, never `Double`, and `Money` is not `Codable`. Rates are `Decimal`; stochastic samples are `Double` only inside the engine. Round to cents with banker's rounding only at reporting boundaries, through `Money`, plus when normalizing typed money input (the New Experiment cash balance), where validation checks the rounded value. Core never formats display strings. Every amount of money displays to the cent (ADR-0025). Prices, dividends and per-share figures go through Presentation's `PriceFormatter`, with the full value in a tooltip (`help(ifPresent:)`) when rounding shortened it; amounts already in whole cents, such as costs, cash, gains and limit prices, use `.currency(code: "USD")`. Stored values keep every decimal.
- **Concurrency (ADR-0003):** Swift 6 mode everywhere. Core is nonisolated with `Sendable` value types. The app and Presentation targets set `defaultIsolation(MainActor.self)` in `Package.swift`. Driven ports are `async` when they do I/O. Use structured concurrency for heavy simulation, with cancellation checks. No Combine, `ObservableObject`, `DispatchQueue` or global mutable state.
- **Persistence (ADR-0021, superseding ADR-0005):** all experiments live in one SQLite database, `~/Library/Application Support/Investment Simulator/experiments.sqlite`, opened by `ExperimentDatabase.open(at:)` as a GRDB `DatabasePool` and reached only through Core's `ExperimentRepository` port (`GRDBExperimentRepository`). GRDB is imported by the Persistence target alone. Money is stored as a decimal string, never a SQLite number. Schema changes are GRDB migrations. If the database can't be opened or migrated, the app shows `DatabaseErrorView` and stops; it never recreates the file. A file a newer build migrated (an unknown migration) isn't opened either, since saving would drop what this build can't read (`ExperimentDatabaseError.newerThanApp`, ADR-0026). Deleting an experiment is permanent. Tests pass the adapter an in-memory `DatabaseQueue`. Old `.invsim` files are not imported; the JSON codec and its DTOs are gone.
- **Market data and secrets (ADR-0012):** prices come from Equibles through `QuoteProviding`. Try the live quote, then fall back to the latest close on `403` or a `stale` quote. A quote's session (`Quote.sessionDate`, ADR-0023) is a close's own, else the New York day of its `asOf`, so a quote at 8 PM in New York counts as that day's even past midnight UTC. JSON prices pass through `Double` once, inside the adapter, via `Decimal(string: String(double))`. The API key lives only in the Keychain (`KeychainCredentialStore`, behind `CredentialStoring`) and is entered in the Settings scene, never in documents, `UserDefaults` or logs. ADR-0019 adds a second Keychain item for the SEC contact email, kept the same way. App-wide services are built once in `InvestmentSimulatorApp` and passed to each window's initializer.
- **Limit-order fills (ADR-0013):** Equibles has no historical intraday prices, so orders fill from daily bars (`DailyPriceProviding`). The rule lives in Core (`Experiment.fillingLimitOrders(from:at:)`): the first session whose high reaches the limit fills the order at exactly the limit price. Only orders open when the check runs can fill, from sessions after the placement session and before today in New York; an order that expired unchecked never fills, because its shares may have been sold again. The user starts a check with the Check Orders button; nothing checks automatically.
- **Buy limit orders and cancellation (ADR-0014):** `BuyLimitOrder` is its own type, separate from the sell `LimitOrder`. An open buy order reserves its cost, so purchases and new buy orders spend only `Experiment.availableCash(at:)`, and `purchasing(_:at:)` takes the time of the purchase. A buy order fills under ADR-0013's session rules when a session's low reaches its limit, at exactly the limit. The fill becomes a `Purchase` with the order's id and a `limitOrderFill` price source. An open order of either side can be cancelled; `cancelledAt` is stored, and an order counts as open only before it, so rebuilding a saved experiment still checks each placement at its own time. A cancelled order never fills.
- **Experiment header (ADR-0015, amended by ADR-0021 and ADR-0023):** an experiment's `name`, `notes` and `createdAt` are optional; the title is the name, else "Untitled" (`LibraryModel.title(for:)`, `MainWindowModel.title`). Starting cash and invested cost are derived in Core, never stored. Unlike Check Orders, held tickers are quoted automatically, through `HoldingsPricesModel`: when the experiment is shown and when holdings grow (`.task(id: heldTickers)` in `ExperimentFooter`), plus Refresh Prices; there's no polling. Refresh Prices (`refreshPrices(holding:)`) also requotes every ticker a stock card asked for on demand, quoted or failed, and is enabled whenever there's any such ticker or any held (`canRefresh(holding:)`). Total Value and Gain/Loss show "—" until every held ticker is priced, and each ticker keeps its last good quote. The price status ("Prices as of", "Getting prices…" or the quote error), a failed save and Refresh Prices live in the experiment's footer (`ExperimentFooter`, PIN-411), not in the header.
- **Market sales (ADR-0016, amended by ADR-0026):** Market Sell sells shares of one purchase, chosen in the sheet (ADR-0022), at a quote, priced as Market Buy is. A `Sale` is its own type, with a two-case `SalePriceSource` (no limit fill), and filled sell orders stay `LimitOrder`s; each stock's Sales table merges both. A sale takes only `availableShares(of:at:)`, so shares in an open sell order stay reserved, and `soldAt` is when the user sold, not the quote's time. The quote's time is stored apart as `quotedAt` (the quote's `asOf`, column `quoted_at` from migration `v2`), nil for sales made before it; it is only shown, while `soldAt` still orders rows, checks shares and replays. Realized gain is rounded proceeds minus the rounded cost of the sold shares (`Purchase.cost(of:)`), for sales and sell fills alike; across partial sales of one purchase the gains can differ from the cash by a cent. Rebuilding an experiment replays sell placements and sales in time order and never adds a sale's proceeds to cash again.
- **Stock cards (ADR-0022, amended by ADR-0023, ADR-0024, ADR-0026 and ADR-0027):** below the Experiment header, `StockCardList` shows a card per ticker, by symbol (`MainWindowModel.stockCards(at:)`): ticker, company name, shares held and average price. A ticker gets a card if it was bought or has an order row showing, so a fully sold stock keeps its card with 0 shares and "—", and one whose only orders expired or were cancelled shows only while Expired & Cancelled is on. Shares held and the average price come from Core (`Experiment.heldShares(of:)` and `averagePrice(of:)` for a ticker); the average weighs each purchase's unrounded price by its held shares, so one purchase's average is its own price. Clicking a card opens its panes (`StockPane`: Overview, Chart, Purchases, Sales, Orders), chosen with a segmented picker, not a `TabView`, which sizes poorly in a scroll view. Expansion and panes live in `MainWindowModel`, never saved. Overview (`StockOverviewPane`) only renders `MainWindowModel.overview(of:)`, a `StockOverview` tested in Presentation (PIN-511). It shows the header's quote of the ticker (`HoldingsPricesModel.lastGoodQuote(of:)`), so a held stock costs no extra request; a card with no shares asks through `priceOverview(of:)`, which leaves a held ticker to the holdings, when its Overview shows, and again if its last shares go while it shows. Below the price and its source label come its change since the close of the latest session before the quote's (`Quote.sessionDate`, `Quote.change(since:)`), shown only once the month's bars load (`RecentSessions`, from `loadLatestSession(of:)`) on or after the quote's session (bars from an earlier day reload through `reloadSessionsIfStale(of:)`), and, with shares held, their market value and unrealized gain (`Experiment.marketValue(of:at:)`, `unrealizedGain(of:at:)`). The cost rounds per purchase as `investedCost` does, so the cards' costs add up to Invested exactly, while each card's market value rounds on its own. Then comes the latest settled session's open, high, low and close. A failed first quote shows its reason; a failed refresh keeps the last good quote and shows no error. Company names load once per ticker as each card appears (`loadCompanyName(of:)`, through `CompanyProfileProviding`); `noData` isn't asked again, other failures are. Chart (`StockChartPane`, ADR-0027) is Research's chart (`PriceChartView` over a `PriceChartModel`, one per card from `priceChart(of:)`, kept for the run, never saved), loading its bars only when shown, except 1M, which the Overview's month fills that day (`keepOverviewBars(_:askedFor:of:)`, PIN-524), and again on a new New York day or Refresh Prices (`MainWindowModel.refreshPrices()`, which the footer calls, PIN-519), with the experiment's trades of the ticker marked: purchases, market sales and sell fills, never unfilled orders, each at its stored price and its session (`Purchase.sessionDate`, `Sale.sessionDate`, a fill's `filledOn`, by `Quote.sessionDate`'s rule). `chartTrades(of:in:)` places them at noon of the session in the user's zone, as the closes are, and leaves out those outside the range shown. The Purchases and Sales Date columns and the sell sheets' purchase picker show a trade at a live quote by its day and time in the user's time zone, and a trade at a close or a limit fill by its New York session day (`PriceDateFormatter.tradeTime`, ADR-0024); a market sale at a live quote shows its `quotedAt`, else `soldAt` (ADR-0026), and one at a close shows the close's session, not `soldAt`. Market Buy sits in Purchases, Market Sell in Sales, and Buy Limit, Sell Limit and Cancel Order in Orders. The sell sheets open for a ticker and offer its purchases still held (`SellablePurchase`), starting on the one acted on, else the first with free shares. Market Buy and Buy Limit for a new ticker, Check Orders and the Expired & Cancelled toggle stay above the cards (`ExperimentActionRow`). The cards are a plain `VStack` in a `ScrollView`, and each table gets an explicit height of up to six rows, since a `Table` in a scroll view has none of its own.
- **Research window (ADR-0019):** one app-wide `Window("Research", id: "research")` scene with `.keyboardShortcut("r", modifiers: [.command, .shift])`. The scene puts itself in the Window menu, so there's no `commands {}` block. A ticker's research is a fixed header (symbol, Buy in Experiment menu, quote) above a `TabView` of `ResearchPane`s (Overview, Valuation, Financials, Dividends, News, Filings), the selected one kept in memory per ticker by `ResearchWindowModel.selectPane(_:for:)` (PIN-505). Open tickers are a `NavigationSplitView` sidebar, not a `TabView`, which can't close tabs on macOS. They're closed from the row. `ResearchWindowModel` is `@State` on `InvestmentSimulatorApp`, like `SettingsModel`, and each ticker gets a `ResearchTabModel` with one `loading`/`loaded`/`empty`/`failed` state per section. Each section has its own Core port (`CompanyProfileProviding`, `ValuationMultiplesProviding`, `FinancialStatementProviding`, `DividendProviding`, `PressReleaseProviding`, `FilingProviding`, `SecurityDirectory`) throwing `MarketDataError`. A per-ticker `404` after the quote has validated the ticker is `noData`, an empty state; `QuoteError` stays unchanged. A tab loads every section at once, except statements, which load per statement and cadence once the Financials pane is selected; closing a ticker cancels its tasks. Open ticker symbols and the selection are saved in `UserDefaults` (`ResearchTickerStoring`) and reopened by `restore()` when the Research window first appears, each loading in full (PIN-442). Equibles serves the data. SEC EDGAR's `company_tickers_exchange.json` (search, exchange, CIK) is downloaded once per launch into memory, with `User-Agent: Investment Simulator <contact email>`. The email is entered in Settings and kept in the Keychain (account `sec-contact-email`), never in source. Without it, EDGAR features are off and Research degrades section by section. `EdgarSecurityDirectory` (an actor) shares one download across callers and keeps no failure, so a newly saved email works without a restart. Search lives in a header across the top of the Research view (`ResearchSearchHeader`, PIN-482): matches replace the detail pane while there are any and open by click. Return opens the top match when the text matches only company names, and otherwise exactly what was typed, because a ticker EDGAR lacks (VTI) could otherwise open a security it merely starts. A ticker EDGAR lacks whose letters appear only in company names is opened from its match instead; it can't be told from a name. The profile's exchange loads as its own section, after the quote, because a directory download can't be cancelled and would hold up dropping an unknown ticker. Filing rows link to sec.gov (`Filing.secURL(cik:)`, the CIK from the same directory lookup as the exchange) once EDGAR has listed the ticker, and to the Equibles page until then, without the email, or for a ticker EDGAR lacks. No Finnhub. Sample responses for adapter tests are in `docs/spikes/PIN-413/`.
- **Library window (ADR-0021, superseding ADR-0011 and ADR-0020):** one app-wide `Window` holds a `NavigationSplitView`: Research and every experiment in the sidebar, the selection in the detail. `InvestmentSimulatorApp` opens the database at launch; if that fails it shows `DatabaseErrorView` and nothing else. `LibraryWindowModel` wraps `LibraryModel` and keeps one `MainWindowModel` per experiment, so a sheet survives switching away. Configure windows only through SwiftUI scene and view modifiers: no `NSWindow` access, no autosave names. Research's Buy in Experiment menu lists the library and calls `LibraryWindowModel.beginPurchase(of:in:)` or `beginBuyLimitOrder(of:in:)`, which select the experiment, wait for its load, then fill the sheet.
- **Sheets (PIN-405):** sheet forms use `.formStyle(.grouped)` and size to their content. A sheet can't be taller than the library window, so `LibraryWindow`'s `minHeight` must fit the tallest sheet (Buy Limit or Sell Limit with every message showing, about nine rows); when a sheet gains rows, check it still fits without scrolling. The `minHeight` is 640, not 480, so a few stock cards show below the Experiment header (PIN-408, ADR-0022).

`AppDelegate` sets the activation policy to `.regular` in `applicationWillFinishLaunching`. A bare SwiftPM executable otherwise launches as a background process with no Dock icon and an unresponsive menu bar. Setting it later, in `didFinishLaunching`, is too late.

`just bundle` assembles the `.app` by hand from `Resources/Info.plist` plus the release binary. The app name and executable name are duplicated across `Info.plist` (`CFBundleName`, `CFBundleDisplayName`, `CFBundleExecutable`) and the `justfile` (`app_name`, `app_bundle`). Change them together, or the bundle will not launch. ADR-0006 also lists `AppMetadata.displayName`; that type has been removed.

The app icon (ADR-0017) comes from the Icon Composer document `Resources/AppIcon.icon` (`icon.json` plus SVG layers). Tune its glass and appearances in Icon Composer (inside Xcode.app). `just bundle` compiles it with `xcrun actool` into `Contents/Resources` (`Assets.car` plus `AppIcon.icns`) before `codesign`. It passes absolute paths, because relative ones once resolved against another directory, and reads the deployment target from `LSMinimumSystemVersion`. `actool` can exit 0 without writing anything, so the next line fails the recipe unless both files exist. `Info.plist`'s `CFBundleIconName` and `CFBundleIconFile` must match `actool`'s `--app-icon AppIcon`. LaunchServices caches icons: after a rebuild, check with `lsregister -f` on the bundle or `killall Dock`, not by relaunching the app, which asks for the Keychain.

## Formatting and lint

- SwiftFormat reads its target Swift version from `.swift-version` (6.2). Its defaults rename Swift Testing functions to raw identifiers, e.g. `` @Test func `display name is investment simulator`() ``.
- SwiftFormat owns trailing-comma style, so `.swiftlint.yml` disables SwiftLint's `trailing_comma` rule.
- Pass explicit paths to SwiftLint (as `just lint` does); otherwise it scans `.build/`.

## CI

`.github/workflows/ci.yml` runs `just lint`, `just test` and `just bundle` on pushes to `main` and on pull requests. It uses the `xcode-27` runner, a GitHub public-preview image, and selects `/Applications/Xcode_27.1.app` to match the local toolchain. When that Xcode is removed from the image, update the path.

CI pins SwiftFormat and SwiftLint by version and SHA-256 in `ci.yml`. When you upgrade either tool locally, update the version and checksum there to match, or CI and local lint can disagree. `release.yml` copies the same pins; bump both workflows together.

## Releases

Releases follow ADR-0018; [docs/releasing.md](docs/releasing.md) is the step-by-step guide for setup, rehearsal, cutting a release and certificate renewal. Pushing a `vMAJOR.MINOR.PATCH` tag on a commit on `main` runs `.github/workflows/release.yml`, which:

1. lints and tests
2. runs `just bundle <version> <run number>` with the Developer ID identity
3. runs `just release-zip` and `just notarize`
4. publishes a GitHub Release with `Investment-Simulator-<version>.zip` and generated notes

Any other `v*` tag, or one on a commit that isn't on `main`, fails before building, and nothing is published.

The committed `Info.plist` version is a development placeholder; never bump it for a release.

The secrets are `DEVELOPER_ID_P12_BASE64`, `DEVELOPER_ID_P12_PASSWORD`, `NOTARY_API_KEY_P8_BASE64`, `NOTARY_KEY_ID` and `NOTARY_ISSUER_ID`. They live in the `release` GitHub Environment, restricted to `v*` tags. The identity's name, `Developer ID Application: Christopher Bartling (RDD45JXSRK)`, is written in `release.yml`.

Rehearse locally with `CODESIGN_IDENTITY=<that name> just bundle 0.1.0 1`, then `just release-zip 0.1.0` and `just notarize 0.1.0`.
